# Design — 照片编辑 / 数据库直接管理 / 手动补录 / 去重覆盖

## 背景
本次改动补齐四类数据维护能力，并为查看器交互做延迟关闭修复。所有改动均围绕"让用户在不重建数据库的前提下修正与扩展数据"展开。

## 决策

### D1. 查看器内编辑仅放开文件名/路径，其余字段只读
- **决策**：编辑表单中经纬度、拍摄时间、尺寸字段一律 `readonly`
- **理由**：经纬度/拍摄时间来自 EXIF，是数据真实性来源；允许手动改写会破坏与原图 EXIF 的一致性，且经纬度错误会导致点位偏移难以排查。文件名/路径属于元数据管理范畴，允许修正。需要改坐标的场景由"手动补录"或重新导入解决。
- **取舍**：放弃了"批量修正坐标"的便利，换取数据可信度

### D2. 查看器 hover 关闭采用 220ms 延迟而非永久悬停
- **决策**：`mouseleave` 启动 220ms 计时器，`mouseenter` frame/`#viewerMeta` 取消
- **理由**：纯永久悬停（不关闭）会让查看器在鼠标离开后滞留，遮挡地图；立即关闭又让用户来不及移动到查看器内。220ms 是从缩略图移向大图的合理过桥时间，与既有 220ms 动画时长一致。
- **取舍**：极慢鼠标移动（>220ms 跨越间隙）可能误关，但概率极低且可重新悬停打开

### D3. 数据库管理默认操作内存数据库，外部文件需显式切换
- **决策**：弹窗打开即展示当前内存 db；外部文件通过「选择 db 文件」按钮显式切换，且切换前对未保存编辑做 `confirm`
- **理由**：内存数据库是用户当前正在使用的，是最常见的编辑对象；外部文件预览是低频需求。默认操作内存库降低认知成本，显式切换避免误改陌生文件。
- **取舍**：用户不能"一眼看到外部文件再决定是否切换"，但通过文件名提示可识别当前数据源

### D4. CSV 覆盖采用按哈希全量增/改/删，而非增量合并
- **决策**：导入 CSV 时以 CSV 为准，库里存在但 CSV 没有的哈希删除，CSV 有的库没有则新增，都有则全字段更新
- **理由**：CSV 是用户在 Excel 等工具里编辑后的"目标状态"，应保持 CSV 与库一致；增量合并会让"删除某行"无法表达。事务包裹保证原子性，失败回滚。
- **取舍**：用户必须导出完整 CSV 再编辑，不能只编辑子集；但语义清晰，不会因漏行误删

### D5. CSV 覆盖后内存模式触发 `rebuildPhotosFromDb` 全量重建
- **决策**：内存模式下 CSV 覆盖后清空 `thumbLayer`/`dotLayer`/`photos`/`hashSet`，从 db 重新 SELECT 重建
- **理由**：CSV 覆盖可能删除大量照片或改坐标，逐项同步内存状态复杂且易错；全量重建语义简单、可靠。重建后 `scheduleRender` 触发地图重绘。
- **取舍**：照片数量大时重建有短暂卡顿，但数据库规模通常在千张以内可接受

### D6. 手动补录经纬度由地图 GCJ02 → WGS84 逆转换
- **决策**：长按地图得到的 `e.latlng` 是 GCJ02 坐标（高德瓦片），保存前用 `gcj02ToWgs84` 迭代逆转换存为 WGS84
- **理由**：数据库与 EXIF 一致使用 WGS84，地图显示时再正向转换。若直接存 GCJ02，海外点位会偏移，国内点位在切换底图时也错位。
- **取舍**：迭代 5 次逼近有微小误差（<1e-6 度），可忽略

### D7. 手动补录 EXIF 时间优先且锁定
- **决策**：选择照片后若有 EXIF 时间，时间字段 `disabled` 并显示照片时间；无 EXIF 才允许手动填写并标记 `approxTime`
- **理由**：EXIF 时间是数据真实来源，不允许覆盖；手动填写的视为估算，需在元信息中标识。与既有导入逻辑（EXIF 时间优先、无则用文件修改时间并标记 approxTime）保持一致。
- **取舍**：用户不能用一张照片的 EXIF 时间去补另一张无 EXIF 照片的时间，但这是合理的真实性约束

### D8. 重复哈希由"跳过"改为"后载入覆盖"
- **决策**：`hashSet` 命中时不再 continue，改为 `UPDATE photos SET 全字段 WHERE hash=?`，统计字段 `updated`
- **理由**：用户多次加载数据库时，后载入的通常是修正后的数据（如重新导入改善了 EXIF 解析），覆盖才能让更正生效。"跳过"会导致修正永远无法落地，与工程约束"后载入为准"一致。
- **取舍**：旧值（含 thumb/EXIF）被覆盖不可恢复，但用户主动加载多次即意图覆盖；Toast 显式提示覆盖数量

### D9. 外部 .db 文件编辑用 FileSystemFileHandle 写回
- **决策**：通过 `showOpenFilePicker` 取 `FileSystemFileHandle`，编辑后 `createWritable` → `write(export())` → `close` 原地写回
- **理由**：保留句柄可多次编辑同一文件无需重复选择；`export()` 输出 `Uint8Array` 直接写入是 sql.js 标准用法。
- **取舍**：仅 Chromium 支持，Safari/Firefox 下外部文件模式不可用（已 toast 提示），内存模式不受影响

### D10. 数据库管理弹窗分页大小响应式
- **决策**：PC（`innerWidth > 760`）10 条/页，手机 5 条/页
- **理由**：手机屏幕高度有限，10 条会撑出视口；5 条保证表格与详情区同时可见。打开弹窗时一次性确定 `pageSize`，不监听 resize（避免分页跳变）。
- **取舍**：横竖屏切换不会动态调整，但用户体验损失可忽略

## 风险与权衡
- **CSV 覆盖不可撤销**：D4 决策下用户误删行无法恢复；通过 `confirm` 二次确认与事务回滚兜底
- **去重覆盖破坏旧值**：D8 决策下旧 thumb/EXIF 被覆盖；Toast 显式提示覆盖数量，用户主动加载多次即接受覆盖
- **手动补录坐标可信度**：D6 逆转换有微小误差；D7 EXIF 时间锁定保证时间可信
- **外部文件浏览器兼容性**：D9 仅 Chromium；降级路径为内存模式，外部文件预览功能不可用而非崩溃
- **查看器延迟关闭体验**：D2 的 220ms 是经验值；若反馈不足可调参，无架构耦合

## 不做（Out of Scope）
- 不支持数据库字段级权限控制（如只读 thumb 列）
- 不支持 CSV 增量合并（仅全量覆盖）
- 不支持手动补录时批量导入多张照片（单张流程）
- 不支持查看器内编辑经纬度/拍摄时间（D1 决策）
- 不支持外部 .db 文件模式下的 CSV 导入导出与内存模式差异（功能一致，仅持久化路径不同）
