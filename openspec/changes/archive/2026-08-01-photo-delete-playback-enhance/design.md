## Context
原照片墙仅支持导入与加载，无删除入口；播放固定 1× 速度、进度条不可拖、播放范围无视觉区分、每次打开播放设置都重置为全时间范围。删除与播放增强均涉及对外可观察行为，需新增 `photo-delete` 与 `photo-playback` 两个 capability。

既有约束：照片去重基于 hash、删除需即时持久化（project_memory 硬约束）、播放只平移视野不动缩放级别、低缩放播放需临时缩略图高亮（photo-render-layering 既有契约）。

## Goals / Non-Goals
**Goals:**
- 提供单张照片删除入口，确认后即时从数据库与地图移除并持久化
- 播放速度可在 0.5×–8× 间实时切换，变更立即生效
- 进度条可拖动跳转，拖动期间暂停自动前进
- 播放期间非本次播放点位视觉降级，便于区分范围
- 播放区间在重复打开设置弹窗时自动带入上次值
- 不引入新依赖，不改变既有照片位置/缩略图/分层渲染契约

**Non-Goals:**
- 不实现批量删除（仅单张）
- 不实现撤销删除（删除即不可恢复，已由确认弹窗保护）
- 不实现播放速度自定义输入（仅 5 档预设）
- 不实现播放区间多组保存（仅记忆上一次）
- 不改变播放「只平移视野不动缩放」的核心机制

## Decisions

### 决策 1：删除入口放在大图查看器内，而非列表或地图右键
**选择**：在大图查看器 `.frame` 右上角放纯图标删除按钮，点击弹确认框。
**理由**：删除是单张照片操作，查看器是用户聚焦单张照片的唯一场景，入口与上下文一致；列表/地图右键会增加发现成本与误触概率。纯图标无文字符合查看器内紧凑布局，hover 变红已有危险暗示。
**备选**：缩略图标记上加删除按钮——已否决，缩略图本身很小，再加按钮拥挤且误触。
**备选**：单独的删除模式——已否决，过度设计，单张删除不需要模式切换。

### 决策 2：删除确认用自定义 modal，而非 `confirm()`
**选择**：新增 `#delModal` 蒙层 + modal，按钮「否」/「是」（红色）。
**理由**：原生 `confirm` 在不同浏览器样式不一、阻塞主线程、无法自定义文案与按钮颜色；项目已有 `.mask`/`.modal` 样式体系（播放设置弹窗复用同套），视觉一致。文案明确「切不可恢复」满足警示要求。
**备选**：`confirm()`——已否决，样式与体验不一致。

### 决策 3：删除即时 `saveData()`，不要求额外「保存数据」
**选择**：`deleteCurrentPhoto` 在数据库 `DELETE` 后立即调 `saveData()` 写盘。
**理由**：project_memory 硬约束明确「删除照片必须立即持久化到数据库文件，无需额外保存」。若仅内存删除，用户关闭页面后数据丢失与用户预期不符（确认弹窗已承诺「立即从数据库文件内删除」）。
**备选**：标记脏数据待手动保存——已否决，违反硬约束与确认文案承诺。

### 决策 4：删除时与播放状态联动
**选择**：若删除的是当前播放照片，`stopPlay(false)`；若是播放列表中其他照片，从 `player.list` 与 `player.listSet` 移除并修正 `player.idx`。
**理由**：当前播放照片被删后无法继续推进，必须停止；列表中其他照片被删后若不同步清理，`tickPlay` 推进到该照片会 NPE。修正 `idx` 保证后续推进不错位。
**备选**：删除时无条件 `stopPlay`——已否决，破坏用户正在进行的播放体验，过度保守。

### 决策 5：速度调整立即重排当前 setTimeout
**选择**：`hudSpeed` 的 `change` 事件中 `clearTimeout(player.timer)` + 按新 `interval()` 重排，不等下一帧。
**理由**：用户切换速度的预期是「立刻按新速度走」，若等当前 setTimeout 到期才切换，4×/8× 下仍要等原 1× 间隔的剩余时间，体验割裂。重排是 O(1) 操作，无性能负担。
**备选**：仅改 `player.speed`，等下次 tick 生效——已否决，4× 下用户感知到延迟。
**备选**：用 `setInterval`——已否决，与既有 `setTimeout` 链式调度不一致，且暂停/恢复处理更复杂。

### 决策 6：进度条用透明 range 叠加在视觉进度条上
**选择**：`#hudSeek` 是 `position:absolute` 的透明 `<input type="range">`，叠在 `.pbar` 上方，仅 thumb（白色圆点）可见；原 `.pbar i` 视觉进度条保留，由 `tickPlay` 同步宽度。
**理由**：保留原视觉进度条样式（3px 高、品牌色填充），不破坏 HUD 整体设计；range 透明只露 thumb，交互语义清晰。`input` 期间 `clearTimeout` 暂停自动前进，避免与用户拖动冲突；`change` 跳转后由 `tickPlay` 重新调度，复用既有高亮与 marker 管理逻辑。
**备选**：直接把 `.pbar` 改成 range——已否决，range 默认样式跨浏览器不一致，3px 高度下 thumb 难以命中。
**备选**：用鼠标事件 + 计算位置——已否决，重复造轮子且移动端 touch 兼容差。

### 决策 7：`input` 期间仅预览不跳转，`change` 才跳转
**选择**：`input` 事件刷新 `hudName`/`hudTime`/`hudBar` 但不改 `player.idx`、不移动地图；`change` 事件才真正跳转。
**理由**：`input` 高频触发，若每次都 `tickPlay` 会高频创建/销毁临时 marker 与平移地图，卡顿且地图抖动。预览只更新文本与进度宽度，开销极小。`change` 在释放时触发一次，跳转开销可接受。
**备选**：`input` 期间也跳转——已否决，性能与体验均差。

### 决策 8：播放区间点位区分用 `pm-out` 类 + 圆点 `setStyle`
**选择**：缩略图模式加 `pm-out` 类（CSS 控制橙边框 + 不透明度 0.5），圆点模式调 `setStyle({fillColor})`；起止时 `applyPlayStyles`/`clearPlayStyles` 批量更新。
**理由**：CSS 类方式与既有 `.active`/`.no-time` 类机制一致，`createThumbMarker` 创建时按 `player.listSet` 判定是否加类，渲染层切换重建 marker 也自动正确。圆点用 `setStyle` 是 Leaflet 原生 API，性能优于重建。批量 `apply`/`clear` 避免每张照片单独操作。
**备选**：播放时整体重建 marker——已否决，与 photo-render-layering 的视口裁剪/分批创建冲突，性能差。

### 决策 9：播放区间记忆用 `localStorage`，file:// 静默忽略
**选择**：`startPlay` 写 `pw_playStart`/`pw_playEnd`，`openPlayModal` 读；`try/catch` 包裹，失败静默。
**理由**：用户反复播放同一区间（如巡检某天）是高频场景，记忆能省去重新选择。file:// 协议下部分浏览器禁用 `localStorage`，抛错会中断播放启动，必须 `try/catch`。静默忽略后回退到全时间范围，行为与原有一致。
**备选**：用 IndexedDB——已否决，过度设计，两个字符串键值用 localStorage 足够。
**备选**：抛错时 toast 提示——已否决，干扰用户且无解决动作。

## Risks / Trade-offs
- **[删除不可撤销]** 确认弹窗文案已明确「切不可恢复」，但用户误点「是」仍丢数据 → 缓解：弹窗「是」按钮红色 + 文案警示；接受，单张删除无需撤销机制
- **[localStorage 在 file:// 失效]** 区间记忆在部分浏览器不可用 → 缓解：`try/catch` 静默回退到全时间范围；不影响其他功能
- **[进度条拖动未释放即关 HUD]** `change` 不触发，`player.idx` 仍为旧值 → 缓解：`stopPlay` 重置 `player.idx`/`list`/`listSet`，下次播放从头开始；接受
- **[pm-out 与 active 叠加]** 当前播放高亮照片若被标记 out，需保证不透明度恢复 → 缓解：CSS `.pm.pm-out.active .pm-box{opacity:1}` 显式覆盖；已验证
- **[速度 8× 下 setTimeout 精度]** 浏览器 setTimeout 最小 4ms，8× 在 1× 间隔 2s 时为 250ms，不受限；但 1× 间隔若很短（如 0.5s），8× 为 62ms 接近精度边界 → 接受，当前 1× 间隔默认 2s，无问题

## Migration Plan
本次为新增功能，无数据迁移。既有数据库 schema 未变（`photos` 表结构与 hash 主键不变），删除操作用标准 `DELETE FROM photos WHERE hash=?`，兼容所有已写入的数据库文件。`localStorage` 键为新增，不影响既有数据。

## Open Questions
- 是否需要批量删除（如按时间范围/按选中）？——可延后，当前单张删除已覆盖主要场景
- 速度档位是否需要持久化（记忆上次速度）？——可延后，当前默认 1× 符合多数场景
- 进度条是否需要显示具体时间 tooltip？——可延后，HUD 已显示当前照片时间
