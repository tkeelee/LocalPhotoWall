# 设计说明：地点搜索框

## 目标
在不引入任何 API Key、兼容 `file://` 与 HTTP 两种打开方式的前提下，提供"输入地名→飞到该点"的即时搜索。核心权衡：**离线可用性优先于覆盖广度**——高频的国内行政区划与知名景区用本地数据集零延迟命中，长尾/海外地名交给在线地理编码兜底。

## 架构

```
搜索框输入 (防抖 350ms, ≥2 字)
        │
        ├─ 本地数据集检索（同步，立即返回前 8 条）
        │     └─ CHINA_PLACES（省市区三级, GCJ-02）
        │     └─ SCENIC_5A（5A 景区, GCJ-02）
        │
        └─ 在线地理编码（异步，补全长尾/海外）
              ├─ 主：OSM Nominatim（5s 超时, AbortController）
              └─ 备：镜像地球 api.mirror-earth.com（8s 超时）
                    └─ 智能冷却：OSM 失败标可疑 + 60s 冷却，
                       冷却期内直走镜像，结束后重试 OSM
```

## 关键决策

1. **本地优先、合并渲染**：本地结果即时展示（即便同时发起了在线请求），在线结果返回后追加在"在线搜索"分隔之下。避免"必须等网络"的卡顿感。

2. **坐标系处理**（与既有纠偏体系一致）：
   - 本地数据集已是 GCJ-02，选中直接 `map.setView`，无需变换；
   - 在线结果多为 WGS84，选中时以 `inChina(lat,lng)` 判定：国内走 `ExifLite.wgs84ToGcj02(lng,lat)` 纠偏后定位，海外直接使用。注意该函数返回数组 `[lng, lat]`，曾误用 `.lat/.lng` 导致飞不过去，已修正为 `g[0]/g[1]`。

3. **降级与降级恢复**：OSM 失败（超时/网络错误/429）→ 降级镜像；并置 `osmSuspect + osmRetryAt=now+60s`。`doSearch` 每次先看是否处于冷却：是则直走镜像，否走 OSM。冷却结束后下一次搜索重新尝试 OSM，成功则清可疑标志切回。

4. **数据缺失容错**：`window.CHINA_PLACES` / `window.SCENIC_5A` 任一未加载（如 file:// 缺失脚本），`localData` 为空，仅走在线搜索，不抛错。

5. **交互细节**：加载圈用 `#searchSpin.on` 切换；结果面板用 `.hidden` 控制；输入 `input` 事件防抖、`blur` 延迟 150ms 收起（避免点结果先触发 blur 收起）、`Esc` 清空收起；点击结果 `setView` 后回填输入框文字并收起面板。

## 验收要点
- 输入"北京""西湖""泰山"等应即时（无需联网）返回本地结果并正确飞到对应缩放级别；
- 断网或 OSM 不可达时，本地结果仍可用，在线部分转入镜像地球或给出"无结果/请求失败"；
- 选中海外在线结果（如"Tokyo"）落点无 GCJ02 偏移，与底图对齐；选中国内在线结果有纠偏。
