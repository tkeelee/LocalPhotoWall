## Context
当前照片墙的数据库持久化工作流分散在导入、加载、补录、删除、编辑五个入口，各入口的持久化时机与校验逻辑不一致：补录/删除/编辑已即时落盘，导入仅条件落盘（需已有工作目录句柄），增量加载仅标记脏不落盘；导入与补录的前置校验标准不同；增量加载只能选文件不能选目录；保存按钮兼具覆盖写入与备份双重语义；数据库管理可直接编辑当前主库。本次变更统一为：所有写操作即时落盘、导入前置校验、增量加载选目录并自动建库、保存按钮纯备份、工作目录记忆、数据库管理独立化。

既有约束（project_memory 硬约束）：删除需即时持久化（已实现）、加载多库重复哈希后载入优先、无 GPS 照片不入库、file:// 用 sql-asm.js。

## Goals / Non-Goals
**Goals:**
- 导入照片前校验数据库已加载且存在持久化目标，未加载时拦截并提示
- 增量加载改为选目录，目录无 `photos.db` 时自动创建空库并加载
- 导入、增量加载、补录、删除、编辑完成后均即时持久化，无需手动保存
- 「保存数据」按钮改为「备份数据库」，仅生成 `photos_YYMMDDHHMMSS_bak.db` 备份，不覆盖主库
- 记忆用户上次工作目录，下次优先使用
- 数据库管理不能编辑当前正在加载的数据库文件，内存模式只读

**Non-Goals:**
- 不实现备份文件管理（查看/还原/删除历史备份），仅生成备份文件
- 不实现备份文件数量上限或自动清理
- 不改变数据库 schema
- 不改变照片去重（哈希判重）与覆盖（后载入为准）策略
- 不改变补录/删除/编辑的既有业务逻辑，仅统一前置校验与持久化时机
- 不实现工作目录的跨设备同步（仅本地 localStorage 记忆）

## Decisions

### 决策 1：导入前置校验在按钮点击层拦截，而非文件解析层
**选择**：在 `btnImport` 点击事件与 `dirInput`/`fileInput` change 事件中前置校验 `!db || (!saveDirHandle && !dbHandle)`，校验失败 toast 提示且不展开菜单/不打开文件选择器。
**理由**：在最早入口拦截，避免用户选完照片后才提示无法落盘，减少无效交互。校验条件除 `!db` 外增加持久化目标判断（`!saveDirHandle && !dbHandle`），因为 `ensureDb` 会自动建内存库导致 `db` 非空但无落盘目标。
**备选**：在 `handleFiles`/`runImport` 内部拦截——已否决，用户已选完照片，体验差。

### 决策 2：增量加载改为选目录，通过 `ensureProjectDir` 复用目录选择
**选择**：`btnLoad` 点击时调 `ensureProjectDir()` 选目录，选中后尝试读取 `photos.db`；不存在则 `new SQL.Database()` + `run(SCHEMA)` 建空库，导出 bytes 写入目录后 `loadDbBytes` 加载。
**理由**：增量加载的核心是「向工作目录的数据库追加数据」，选目录比选文件更契合工作流；自动建库消除用户手动创建空库的割裂体验。复用 `ensureProjectDir` 保证目录选择与记忆逻辑统一。
**备选**：保留选文件模式，额外加「新建空库」按钮——已否决，增加操作步骤，且无法自动关联工作目录。

### 决策 3：所有写操作无条件 `saveData`，由 `ensureProjectDir` 引导选目录
**选择**：`finishImport` 删除 `if (saveDirHandle && dbDirty)` 条件改为无条件 `saveData()`；`reportLoad` 末尾追加 `saveData()`。`saveData` 内部 `ensureProjectDir` 在无目录句柄时弹目录选择器。
**理由**：与补录/删除/编辑的即时持久化行为对齐，消除「需手动保存」的不一致。`ensureProjectDir` 已有降级逻辑（目录→文件句柄→下载），保证最终落盘。
**备选**：保留条件保存，仅亮脏标记——已否决，违反「写操作即时持久化」统一目标，用户易丢数据。

### 决策 4：备份文件名用秒级时间戳 `photos_YYMMDDHHMMSS_bak.db`，不扫描序号
**选择**：备份名格式 `photos_YYMMDDHHMMSS_bak.db`，YY 为两位年份，HHMMSS 为时分秒。直接用当前时间生成，不扫描目录已有备份取序号。
**理由**：秒级精度在人工操作场景下冲突概率极低（用户连续点击备份间隔远超 1 秒）；省去目录扫描的异步开销，实现简单。两位年份 YY 节省文件名长度，且 100 年内无歧义。
**备选**：`photos_YYYYMMDD_XXX_bak.db` 扫描序号——已否决，需异步遍历目录，且用户原提案已改为时间戳格式。
**备选**：毫秒级时间戳——已否决，文件名过长且无必要精度。

### 决策 5：`saveData` 直接覆盖主库不自动备份，`btnSave` 改绑独立 `backupDb`
**选择**：`saveData` 的 `writeToDir` 直接覆盖 `photos.db`，不再在覆盖前自动备份旧版；备份职责完全交由 `btnSave` 改绑的新函数 `backupDb`，后者复制当前主库为 `photos_YYMMDDHHMMSS_bak.db`，不删除/覆盖主库。
**理由**：用户明确要求「保存到数据库不需要触发备份，只有主动点击备份才需要备份」。原 `writeToDir` 每次覆盖都生成 `photos_YYYYMMDDHHMMSS.db` 备份会造成备份文件泛滥；备份语义统一收敛到 `backupDb` 一个入口更清晰。即时持久化已保证主库始终最新，旧版丢失风险由用户主动备份兜底。
**备选**：`writeToDir` 保留覆盖前自动备份——已否决，违反「仅主动点击备份」要求且产生大量备份文件。

### 决策 6：工作目录记忆用 `localStorage` + `showDirectoryPicker({id})`
**选择**：`ensureProjectDir` 调 `showDirectoryPicker({ id: 'pw_project_dir', mode: 'readwrite' })`，浏览器自动记忆授权目录。同时 `localStorage` 存 `pw_last_dir_name` 与 `pw_last_dir_time`，弹窗前 toast 提示「建议选择上次的目录「xxx」」。
**理由**：File System Access API 的 `id` 参数原生支持目录记忆，浏览器在后续调用时优先指向上次授权位置；`localStorage` 存目录名用于提示文案。`try/catch` 包裹 localStorage 防止 file:// 禁用时中断。
**备选**：仅用 `localStorage` 存目录名，不用 `id`——已否决，`id` 能让浏览器自动定位目录，体验更好。
**备选**：存完整目录句柄到 IndexedDB——已否决，句柄序列化复杂且权限需重新授权，过度设计。

### 决策 7：数据库管理内存模式与当前加载文件均只读，独立文件可编辑
**选择**：`openDbManage` 内存模式下 `readonly=true`，禁用「保存修改」「导入 CSV 覆盖」按钮、双击单元格不进入编辑，描述文案标注「只读预览」。`pickDbFileForManage` 选中文件后经 `isCurrentLoadedDb(handle)` 比对（目录模式比 `handle.name === 'photos.db'` + `saveDirHandle.resolve` 同目录；文件模式比 `handle.name === dbHandle.name` + `getFile` 比对 size/lastModified）：是当前加载文件则 `readonly=true` 以只读模式加载，数据来源标识「只读预览，当前正在加载的数据库」；否则 `readonly=false` 可编辑，保存写回原文件。
**理由**：当前主库正在被导入/加载/补录/删除/编辑流程读写，管理弹窗若同时编辑会导致数据不一致与并发写冲突。用户在管理弹窗选择当前文件时多为查看而非编辑，直接拒绝会打断流程；改为只读加载既满足预览需求又避免并发写。独立外部文件无并发风险，保持可编辑。
**备选**：选择当前文件时直接拒绝并提示——已否决，用户已选完文件，拒绝体验差，且与「只读预览」目标等价但更生硬。
**备选**：完全移除内存模式，强制选文件——已否决，丢失快速预览当前数据的能力。
**备选**：内存模式可编辑但加锁——已否决，锁机制复杂且与即时持久化冲突。

### 决策 8：增量加载改为双选项菜单，「初始空间」复用 `loadDbFromDir`
**选择**：`btnLoad` 点击弹出 `#loadMenu` 菜单，含两个 `.menu-item`：「增量加载」（`data-act="file"`）走原 `pickDbFile()` 选文件追加合并；「初始空间」（`data-act="dir"`）走新 `loadDbFromDir()` 选目录、读取 `photos.db`、不存在则 `new SQL.Database()`+`run(SCHEMA)` 建空库导出 bytes 写入目录后加载。`loadDbFromDir` 用独立授权 id `pw_load_source`（与工作目录 `pw_project_dir` 区分），首次使用时将源目录同时设为 `saveDirHandle` 工作目录；返回 `Promise<boolean>` 供引导流程判断成功与否。
**理由**：原提案「全量改为选目录」会丢失「选已有 db 文件追加」的便捷入口（用户可能有多个独立 db 文件散落各处）。双选项菜单兼顾两种场景：「初始空间」对应工作目录的自动建库流程，「增量加载」保留文件级合并。独立 id 避免浏览器把源目录选择与工作目录选择的授权记忆混淆。
**备选**：仅保留选目录模式——已否决，丢失文件级合并入口。
**备选**：菜单加第三项「新建空库」——已否决，与「初始空间」选目录自动建库重复。

### 决策 9：未初始化点击导入/补录时自动引导，两条提示分段延时 + 防重入锁
**选择**：`btnImport`/`btnManual` 点击时若 `!db || !hasPersistenceTarget()`，加 `initGuard` 防重入锁后输出提示 A「请先加载数据库文件再导入/补录（…需写入数据库并按哈希判重）」，延时 2.5s 后输出提示 B「检测到未初始化，正在引导您选择初始空间...」，再延时 1.5s 后调 `loadDbFromDir(true)`（`skipHint=true` 跳过内部提示避免覆盖 B），完成后释放 `initGuard`。
**理由**：用户要求「都知道错在哪里且知道要做什么，系统要自己做」——仅提示错误不够，需自动引导到解决方案。两条提示分开输出保证用户先理解错误原因再看到引导动作，避免单条信息过载。`skipHint=true` 防止 `loadDbFromDir` 内部的「请选择要加载数据库的目录」覆盖提示 B。`initGuard` 防止双击或事件冒泡触发两次引导导致提示 AABB 重复。
**备选**：单条提示后立即弹选择器——已否决，用户来不及看清错误原因，且 toast 与原生选择器同时弹出会互相遮挡。
**备选**：仅提示不自动引导——已否决，违反用户「系统要自己做」要求。

### 决策 10：增量加载仅在 `added || updated` 时落盘，全量重复不写入
**选择**：`reportLoad` 末尾以 `var hasChange = r.added || r.updated;` 判断，仅 `hasChange` 为真时调 `saveData(true)` 静默落盘并在提示文案追加「已保存到 xxx/photos.db」；`hasChange` 为假时仅输出加载统计，不落盘、不提示已保存。
**理由**：用户反馈首次增量加载后再次点击重复显示「已保存到 xxx.db」。当本次加载全部为重复哈希（`added=0, updated=0`）时主库内容未变，写入是无效 I/O。仅在有实际变更时落盘既符合「即时持久化」语义（有变更才需持久化）又避免误导性提示。
**备选**：无条件落盘——已否决，产生误导性「已保存」提示且无谓写盘。

## Risks / Trade-offs
- **[增量加载改为双选项菜单]** 用户习惯单按钮直选文件，改为菜单多一步 → 缓解：菜单文案与描述明确区分两个选项；接受，兼顾文件合并与目录建库两种场景
- **[导入时弹目录选择器]** 首次导入需多选一次目录 → 缓解：目录记忆后后续自动复用；接受，保证数据落盘
- **[备份秒级冲突]** 同秒内多次备份文件名相同 → 缓解：概率极低（人工操作间隔 >1s）；接受，不额外处理
- **[管理只读困惑]** 用户在内存模式想编辑但按钮禁用 → 缓解：描述文案明确「只读预览，如需编辑请选择其他 db 文件」；接受
- **[当前文件校验不完美]** FileSystemFileHandle 无直接 `===` 比较，用 name+size+lastModified 三元组 → 缓解：三元组碰撞概率极低；接受
- **[localStorage 在 file:// 失效]** 目录记忆在部分浏览器不可用 → 缓解：`try/catch` 静默回退；不影响其他功能

## Migration Plan
本次为行为变更，无数据迁移。数据库 schema 不变（`photos` 表结构与 hash 主键不变）。备份文件名为新增产物，不影响既有 `photos.db`。`localStorage` 键 `pw_last_dir_name`/`pw_last_dir_time` 为新增。既有 `photos_YYYYMMDDHHMMSS.db` 格式的旧备份文件不受影响（新备份用 `_bak.db` 后缀区分）。

## Open Questions
- 备份文件是否需要定期清理提示（如超过 10 个时提醒）？——可延后，当前仅生成不管理
- 增量加载选目录后是否需要支持选多个目录批量加载？——可延后，当前单目录
- 工作目录记忆是否需要「切换目录」入口（遗忘当前记忆）？——可延后，重新选目录会自动更新记忆
