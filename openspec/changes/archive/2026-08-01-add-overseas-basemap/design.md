## Context
当前项目使用 Leaflet + 高德公共瓦片（免 Key），高德瓦片仅覆盖国内，海外为空白。照片点位经 exif.js 处理：境外 `outOfChina` 为真时坐标不做 GCJ02 偏移，即海外照片点位为原生 WGS84。这一既有约束决定了海外底图必须选用 WGS84 瓦片源才能与点位对齐，无需额外纠偏逻辑。

## Goals / Non-Goals
**Goals:**
- 海外区域有可用的标准/卫星底图，免 Key、免后端
- 国内/海外切换对用户透明，无需手动选择
- 不破坏国内高德瓦片的既有精度与坐标系
- 为未来离线下载预留可启用路径

**Non-Goals:**
- 不实现国内外的无缝拼接（同一视野内国内海外瓦片同时显示）——采用按中心点整体切换
- 不引入付费瓦片服务或 API Key
- 不在本次启用离线下载功能（受 OSM CORS 限制，需换源才能启用）
- 不做海外地名的中文化（OSM/Esri 标注为当地语言/英文）

## Decisions

### 决策 1：按地图中心点整体切换，而非分区叠加
**选择**：`moveend` 时按中心点判定区域，整体移除/加载一整套底图。
**理由**：分区叠加（国内高德 + 海外 OSM 同视野）需处理瓦片边界接缝、两套坐标系在交界处的错位，复杂度高且观感差；整体切换实现简单、无接缝问题，且用户平移到目标区域时底图即就绪。
**备选**：分区叠加——已否决，理由如上。

### 决策 2：海外底图源选择
**选择**：
- 标准：`{s}.tile.openstreetmap.org`（OSM 标准图，PNG）
- 卫星：`server.arcgisonline.com/.../World_Imagery`（Esri，JPG）
- 标注：`server.arcgisonline.com/.../World_Boundaries_and_Places`（Esri，PNG）

**理由**：三者均为 WGS84、全球覆盖、免 Key、无配额限制（合理使用下）。Esri 卫星图全球覆盖且分辨率高；OSM 标准图地名丰富。
**备选**：CARTO Voyager（样式更现代且支持 CORS，便于离线下载）——作为离线启用时的替代源在注释中标注，本次显示用仍用 OSM。

### 决策 3：海外点位不做 GCJ02 纠偏
**选择**：复用 exif.js 的 `outOfChina` 边界判定，海外点位保持 WGS84。
**理由**：海外底图为 WGS84，海外点位本就为 WGS84，天然对齐；若强行套用 GCJ02 纠偏反而会引入偏移。国内点位仍走 GCJ02 对齐高德瓦片，两套机制互不干扰。
**备选**：统一用 WGS84 + 全球瓦片——已否决，会损失国内高德瓦片的精度与中文地名。

### 决策 4：底图切换逻辑收敛为 `applyBasemap()`
**选择**：将原 `toggleLayer` 中分散的 `addLayer/removeLayer` 收敛为单一 `applyBasemap()`，按「inChinaNow × isSatellite」四象限统一管理。
**理由**：新增海外维度后，原直接增删逻辑会组合爆炸；统一入口保证状态一致性，切换图层与切换区域走同一路径。
**备选**：保留分散逻辑——已否决，状态难维护。

### 决策 5：离线下载代码保留但禁用
**选择**：离线下载的 UI（按钮、弹窗、进度取消）、事件绑定、下载流程（`computeOverseasTiles`、`downloadOfflineTiles` 等）全部以注释形式保留；`offlineReady` 恒为 `false`，瓦片层始终走远端。
**理由**：OSM 瓦片服务不支持 CORS，`fetch` 下载会被拦截；强行启用需换 CORS 友好源（如 CARTO Voyager）。保留代码避免未来重写，且注释中写明启用步骤。
**备选**：直接删除离线下载代码——已否决，未来启用需重写；保留成本低于重写成本。

### 决策 6：自定义 `offlineTileLayer` 本地优先、远端兜底
**选择**：重写 `L.tileLayer` 的 `createTile`，`offlineReady` 为真时先读 `tiles/<id>/<z>/<x>/<y>.<ext>`，404 再回源；为假时直接回源避免海量 404。
**理由**：离线启用后需无缝回退到远端；未下载时避免每块瓦片都发一次本地 404 请求拖慢加载。

## Risks / Trade-offs
- **[海外网络不稳定]** OSM/Esri 服务在国内访问可能慢或被墙 → 缓解：保留离线下载路径，未来可预下载；当前接受远端依赖
- **[中心点判定边界穿越抖动]** 地图中心点恰好在国境边界附近时，微小平移会反复触发切换 → 缓解：仅在 `moveend` 触发，且仅当区域确实变化时才切换并 Toast；可接受
- **[海外地名非中文]** OSM/Esri 海外标注为当地语言/英文 → 接受，与原需求"显示境外详情"一致，不要求中文化
- **[离线下载默认禁用]** 用户无离线入口 → 接受，因 CORS 限制无法直接启用；启用路径已在注释中 documented
- **[两套坐标系共存]** 国内 GCJ02 + 海外 WGS84 在边界视野可能轻微错位 → 接受，整体切换策略下用户不会同屏看到两套瓦片接缝

## Migration Plan
本次为新增能力，无数据迁移。已写入的数据库与照片点位不受影响：海外点位本就存为 WGS84，国内点位本就存为 GCJ02，仅底图切换逻辑变化。

## Open Questions
- 离线下载启用时机与瓦片源切换（CARTO Voyager）是否在下一变更中推进？——可延后，不影响本次行为契约。
